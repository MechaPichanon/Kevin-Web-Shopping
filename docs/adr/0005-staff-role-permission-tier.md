# Staff becomes a real permission tier: catalog and orders, not users

`users.role` has allowed `staff` since the original schema, but `requireAdmin` (`backend/middleware/auth.js:31`) only checks `role !== "admin"`, so staff has always been permission-identical to customer. This is being built out rather than left dead: staff gets the same access as admin to product and order management (product CRUD, order status/payment updates, discount codes, low-stock view), but not user management (`/users` CRUD) or role assignment — only admin can promote/demote a user's role, including to/from staff itself, to avoid privilege escalation through a lower tier. Requires a new `requireStaffOrAdmin` middleware alongside the existing `requireAdmin`, and re-gating the product/order/discount-code admin routes to use it while `/users` routes keep `requireAdmin` exclusively.
