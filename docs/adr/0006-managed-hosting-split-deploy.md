# Deploy on managed hosts (Vercel + Railway + Supabase + OpenRouter), not one cloud VM

Supersedes `0001`. The single free cloud VM it assumed wasn't available: Oracle Always Free isn't available in Thailand, and Hugging Face free CPU Spaces became PRO-only (July 2026). The demo is instead split across managed hosts, all in Singapore to keep the backend next to the database (measured: Thailand → Supabase US East was ~263 ms per query): the Next.js storefront on Vercel Hobby (`sin1`), the FastAPI chatbot and the Express API as two always-on Railway Pro services, Postgres/pgvector plus uploaded images on Supabase Free (Storage buckets `products` public, `slips` private, served through a 302 from Express `GET /uploads/:file` so DB rows keep `/uploads/<file>`), and both the chat LLM and the bge-m3 text embeddings on OpenRouter (`EMBED_BACKEND=openrouter` — same vectors as Ollama, cos ≥ 0.9999, so stored embeddings stayed valid). Ollama is now local-dev only. CLIP image search stays in-process in the chatbot, with its weights cached on a Railway Volume (`HF_HOME=/models`) rather than baked into the image.

Railway was chosen over Google Cloud Run (~$0.65/month) because both backends assume an always-on process — the hourly auto-confirm `setInterval`, embedding calls fired after an admin save has already replied, in-memory chat context — and Cloud Run would have needed workarounds for each plus cold starts. Cost: Railway Pro $20/month (includes $20 of usage; estimated use ~$11–12), Compute hard limit $30, everything else on free tiers; OpenRouter is pay-per-call (~US$0.00004 per chat message). Services are to be deleted and Pro cancelled after the thesis defense.
