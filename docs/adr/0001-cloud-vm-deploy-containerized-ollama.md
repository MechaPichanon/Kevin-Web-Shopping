# Deploy to a public cloud VM with containerized Ollama, not a host machine

The thesis demo must be reachable remotely by the committee, so the site deploys to a public cloud VM (no GPU) rather than running locally at the defense. This supersedes the dev-time assumption documented in `CLAUDE.md` that Ollama runs on the developer's **host machine** outside Docker — a cloud VM has no such host, so Ollama (kept only for `bge-m3` embeddings, CPU-only is acceptable at thesis catalog scale) runs inside the VM/containerized instead, and the chat LLM migrates to OpenRouter (already planned in `CLAUDE.md`) rather than staying on local Ollama, since CPU-only `qwen2.5:7b` inference on a VM would likely be too slow for a live demo. The same no-GPU constraint means the planned CLIP image-search model (`clip-ViT-B-32`) also runs CPU-only in this environment.
